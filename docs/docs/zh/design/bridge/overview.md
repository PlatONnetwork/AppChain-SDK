# 简介

AppChain-SDK提供了内置的桥接机制，使得以PlatON作为L1和基于AppChain-SDK开发的L2之间可以进行跨链通信。这个桥接机制可以传输任意的消息和数据。

桥接机制的实现依赖于L1和L2上的代币合约的映射。这个映射关系确保了在资产跨链过程中正确地生成和销毁代币。

在资产转移的过程中，资产被锁定在L1的合约中，对应数量的代币在L2中生成。而当资产从L2中提取时，销毁对应数量的代币，解锁L1对应的资产。这一过程由部署在L1和L2的合约完成，以确保资产转移安全性和透明性。

!!! note "默认启用"

    跨链桥作为共识的一部分，默认情况下是启用的，并且无法关闭，因为它是基于AppChain-SDK开发的L2网络正常运行所必需的。作为原生跨链桥，它内置在区块链协议中，无需额外的第三方解决方案或插件。

    如果您选择使用其他的跨链机制，那么您需要自行进行定制，并且无法保证与L2基础设施的兼容性。


### 跨链消息是如何工作的？

#### 状态同步:  实时同步

L1和L2之间的消息传递是通过状态同步机制来实现的，称为StateSync。此过程涉及到系统调用。

查看[状态同步文档](./statesync.md)了解详情。

#### Checkpoints: 确保应用链活跃和关联检查点

当消息从L2传递到L1时，验证人提交checkpoint，这些checkpoint仅包含退出事件根的L2状态的快照，不包括所有交易。Checkpoint为客户端充当参考点，验证人周期性将发生在L2上的所有交易的检查点提交到L1。Checkpoint同时确保L2的活跃性并提交给L1相关的合约。

查看[Checkpoints文档](./checkpoint.md)了解详情。

#### 桥状态：跟踪事件处理状态

桥存在以下3种状态：

- **Pending:** 事件正在等待打包。
- **Committed:** 事件已转发到L2。
- **Executed:** 事件已提交，状态已执行，状态以改变.

#### 资产：支持ERC20

目前仅支持ERC20代币标准。
